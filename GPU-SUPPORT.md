# Поддержка видеокарт

reframe++ пишет видео аппаратным кодировщиком видеокарты. Здесь — что именно
поддерживается, что делать, если кодировщика нет, и как проверить свою машину.

Всё ниже про **H.264** — единственный кодек, которым программа пишет сейчас.
HEVC и AV1 в коде есть и определяются при диагностике, но выбрать их в
интерфейсе пока нельзя.

## Проверить свою машину

Запустите `reframe-cli.exe` из папки с программой. В разделе
`Hardware encoders:` перечислено всё, что нашлось:

```
Hardware encoders:
  [Media Foundation] H.264 - NVIDIA H.264 Encoder MFT
  [Media Foundation] HEVC - NVIDIA HEVC Encoder MFT
  [NVENC] H.264 - NVENC (direct, nvEncodeAPI64.dll)
```

Пустой список означает, что аппаратного кодировщика в системе нет ни одного —
запись пойдёт на процессоре.

## Как выбирается кодировщик

По порядку, первое подходящее:

1. **NVENC** напрямую через `nvEncodeAPI` — на видеокартах NVIDIA.
2. **AMF** напрямую — на видеокартах AMD.
3. **Media Foundation** — аппаратный кодировщик любого вендора через системный
   MFT. Так работает Intel Quick Sync, а также NVIDIA и AMD, когда прямой путь
   недоступен.
4. **Другая видеокарта в этом же компьютере.** Если у карты, которая держит
   экран, кодировщика нет, а у второй он есть, кадры переезжают на неё общей
   текстурой и кодируются там.
5. **Процессор** — программный кодировщик Windows. Медленно, но работает
   везде.

Выбор можно переопределить вручную в настройках: и видеокарту, и кодировщик.

## NVIDIA

| Поколение | Примеры | H.264 | Заметки |
|---|---|:---:|---|
| Fermi (2010) | GTX 400, GTX 500 | ✗ | NVENC ещё не существовало — только процессор |
| Kepler (2012) | GTX 600, GTX 700, GT 730 | ✓ | Через Media Foundation: драйверы для Kepler остановились на ветке 47x, прямой NVENC требует новее |
| Maxwell (2014) | GTX 745–750 Ti, GTX 900 | ✓ | GTX 900 умеет ещё и HEVC |
| Pascal (2016) | GTX 1050–1080 Ti | ✓ | |
| Turing (2018) | GTX 1650–1660, RTX 20 | ✓ | Заметно лучше картинка при том же битрейте |
| Ampere (2020) | RTX 30 | ✓ | |
| Ada (2022) | RTX 40 | ✓ | Плюс AV1, у старших моделей два кодировщика |
| Blackwell (2025) | RTX 50 | ✓ | |

**Прямой NVENC требует драйвера 570 или новее.** На более старом драйвере
программа не падает и не отказывается писать — она переходит на кодировщик
NVIDIA через Media Foundation. Это тот же самый блок видеокарты, просто с чуть
меньшим контролем над настройками.

**Без кодировщика вообще:** GT 1030, MX150, MX250 и другие карты на чипе GP108 —
у них NVENC физически вырезан, хотя поколение Pascal. Запись пойдёт на
процессоре.

## Когда аппаратного кодировщика нет

Программа не отказывает в записи. Она берёт программный кодировщик Windows —
видеокарта при этом всё равно масштабирует кадр и переводит цвет, процессор
только сжимает. В журнале это выглядит так:

```
this GPU has no hardware encoder - encoding on the processor instead
encoder input: NV12 in system memory
```

Чего ожидать: четырёхъядерный процессор десятых годов уверенно тянет 1280×720
при 30 fps, 1080p при 60 fps — уже нет. Если запись дёргается, снизьте в
настройках разрешение и частоту.

**Если в компьютере есть встроенная графика Intel, но она выключена в BIOS** —
включите её (пункт называется `iGPU Multi-Monitor`, `IGD Multi-Monitor` или
`Integrated Graphics`). Монитор к ней подключать не нужно: программа сама
заметит вторую видеокарту и начнёт кодировать на ней, оставив захват на
основной. В журнале появится строка вида:

```
Radeon HD 7670M cannot encode - encoding on Intel HD Graphics 2500 instead
```

## Ноутбуки с двумя видеокартами

На гибридных ноутбуках экран обычно принадлежит встроенной графике, а дискретная
карта включается только под нагрузкой. Программа захватывает экран у той карты,
которая его держит, а кодирует на выбранной в настройках — кадры переезжают
между картами общей текстурой.

Если драйвер такой обмен не разрешает, запись не прерывается: она продолжится на
карте захвата, а причина будет записана в журнал.

## Виртуальные и удалённые машины

- **Microsoft Basic Render Driver** — программный адаптер без кодировщика,
  запись пойдёт на процессоре.
- **Сессия RDP** — Desktop Duplication в ней недоступна, останется захват окна
  через Windows.Graphics.Capture.
- **Виртуальные машины и виртуальные мониторы** (Hyper-V, Parsec, Sunshine) —
  зависит от того, пробрасывается ли настоящая видеокарта; если нет,
  кодировщика не будет.
